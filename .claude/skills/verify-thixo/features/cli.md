# The thixo command

The `thixo` command (package `thixo-cli`) builds an app from its folders and runs it, the way `next` does: `thixo dev` builds, deploys, serves and rebuilds on change, `thixo build` and `thixo start` do the same in two steps, `thixo compile` and `thixo new plugin` work on plugins, `thixo agent` calls the authoring tools of a running dev server as a named user, `thixo registry list` and `thixo release` show what the local registry holds, and `thixo authoring` shows and lifts the authoring guard's blocks (`authoring-guard.md`).

## Sub-features

- `cli-build` bundles `api/`, `app/slots.ts` and the config for Node into `.thixo/build/server.mjs` (packages external), bundles `app/shell.tsx` into `.thixo/build/client/` with an `index.html`, compiles every folder in `plugins/`, writes `.thixo/build/manifest.json`, and exits 1 if any plugin fails.
- `cli-start` serves a build: `/_thixo/*` and `/api/*` to Thixo, files from the client build, and `index.html` with a Content-Security-Policy for every other GET. It creates `.thixo/signing-key` (mode 600) and deploys `plugins/` first.
- `cli-dev` does what start does from source, writes `.thixo/agent-key` (mode 600) and `.thixo/dev.json`, passes the key to `createThixo` as `config.agentKey`, and rebuilds on change without exiting on an error.
- `cli-compile` compiles a plugin folder or `.thx` file against the project's real compile env and prints the summary in the registry's words (the same lines as `thixo agent check` and the plugin browser), the scopes, the technical details, the manifest and the output size, or `file:line:col code message` errors. Outside an app folder it needs `--project <app>`.
- `cli-new-plugin` scaffolds `plugins/<name>/plugin.thx` with a fresh `plg_` id (18 hex characters, as create-thixo-app makes them) and prints the layout line to paste, with the slot's real path (`"main/todo-row": "<name>"` for a child slot).
- `cli-not-deployed` keeps the last release when a folder the layout names stops compiling, and says so: `not deployed: the layout names plugins/<folder>, which did not compile (see above)`.
- `cli-agent` posts `{ tool, as, input }` with `x-thixo-agent-key` to `/_thixo/authoring/tool`, with shortcuts for submit, check, search, read, fork, use and describe. A tool's own name (`read_plugin`, `search_registry`, `describe_app`) takes the shortcut's arguments. A reply with `ok: false` (a failed check or submit) exits `1`, as a refusal does.
- `cli-registry` prints the plugins, versions, visibility and author, and the current release's layout.

## How to get to it (user POV)

- Run `npx thixo dev [dir]` in an app folder (one with `thixo.config.ts`). The default port is 3000; `--port` or `$PORT` change it, and `--port 0` picks a free one.
- Run `npx thixo build [dir]`, then `npx thixo start [dir]`.
- Run `npx thixo compile <plugin folder or file> [--out dir] [--json] [--project dir]`. A folder outside an app needs `--project <app>`: a plugin compiles against the app it fills.
- Run `npx thixo new plugin <name> --slot <slot> [--personal <folder>] [dir]`. The slot is its name (`todo-detail`) or its export name in `app/slots.ts` (`todoDetail`). Only a default plugin's folder in `plugins/` has an id; `--personal` makes one without, for `thixo agent submit`.
- Run `npx thixo agent <tool> --as <user> ...` while `thixo dev` runs.
- Run `npx thixo registry list [dir]` and `npx thixo release [dir]`.
- Run `npx thixo --help` or `npx thixo <command> --help`.

## Gotchas

- `thixo dev` and `thixo start` need an app whose `node_modules` resolves `thixo`, `thixo-node` and React. Inside the repo the workspace does that; `launch.mjs` links the repo's `node_modules` into its temp copy.
- The deployment id is the git sha when the app is inside a git work tree, else the first 12 hex characters of the build hash, a hash of the plugin sources. It names the code deployed, not the release: a layout-only change keeps the same deployment id and makes a new release id. Versions are found by source hash, so nothing is stored twice.
- Moving or renaming a default folder while `dev` runs can show a `deployed  release` line for the half-done state before the last one. Read the last line.
- `cli.mjs` runs in the copy, and `cleanup.mjs` deletes the copy. To compile after cleanup, use `--cwd examples/<name>`.
- The bundle is re-imported on each change to `api/`, `app/slots.ts` or `thixo.config.ts`, so in-memory app state (the todo example's `db.ts`, the CRM's deals) resets. A change in `plugins/` only redeploys and keeps it. Files outside `api/`, `app/`, `plugins/` and the config are not watched, and there is no live reload: reload the page after `client rebuilt`.
- `--json` means two things: on `compile`, `registry list` and `release` it asks for JSON output, and on `agent` it is the tool's input, so `agent` uses `--raw` for the raw response.
- Do not run two `thixo dev` servers on one project: they share `.thixo/data.sqlite`, and `agent-key` is rewritten on every start.
- `dev` and `start` listen on `127.0.0.1`. A port in use stops with `Port <n> is already in use`.
- The page's CSP is `script-src 'self'`. Plugin code is imported by address (`/_thixo/plugins/<id>/<n>.js?u=…&e=…&k=…`, a five-minute ticket from the load reply), not from a `blob:`.
