## Verified

- **render-clock, render-input: the arena tests drive both, with compiled programs.**
  `npm test`
  Saw: `# pass 314 # fail 0` (core), `# pass 5 # fail 0` (cli), `# pass 23 # fail 0` (bench). The bench suite "the
  host drives the clock and input, and the program can't get past it" has 10 tests, all ok:
  - the default clock runs: frames > 30, time > 1
  - a never-played host clock: `{ frames: 0, time: 0, spins: "0", clicks: 0 }`, even with an effect that sets state
    on every render and a click on the button
  - `step(0.5)` then `step(0.25)`: frames 2, time 0.75
  - `pause` after 300 ms: time stays under 0.6 through the 1.9 s poke
  - `step(10)` then `play`: time is between 11 and 14
  - `step` while playing: error `step runs only while the clock is paused`
  - input on: `inside true`, with `click` and `keydown` said
  - input turned off and on again: `inside true`, with `click` said
  - `input: false`, and `setInput(false)`: text `inside false down false keys [] hits 0` and nothing said. The program
    put `pointerEvents: "auto"`, `tabIndex`, `onFocus` and an `<input onInput>` in the way.
  Before the change: on `origin/main` the same suite failed 6 of its first 8 tests, for example
  `kept running after pause: {"frames":132,"time":2.417,"spins":"many","clicks":2}`. The step-while-playing and
  on-again tests were added after the change.

- **render-clock, render-input: a hover card, mounted with the built `@thixo/react` (dist) in headless Chromium.**
  The card was compiled with `thixo compile <card> -o card.js --modules modules.json` (exit 0). A scratch driver
  mounted it with `{ clock: "host", input: false }`, called `step(1.5)`, played on `mouseenter` and paused on
  `mouseleave` on the host's element.
  Saw:
  - Text was `""` right after `mount` and `"t=1.50 spins=1 inside=false"` right after `step`, in the same call. The
    box was `inert: true`.
  - After hovering for 1 s, then clicking and pressing Enter: `"t=2.52 spins=many inside=false"`, `said: []`, and the
    host's element saw `"enter"`.
  - After leaving, and again 1 s later: the text stayed `"t=2.52 …"`.
  - After `setInput(true)`, hovering and clicking: `"inside=true"`, `said: ["clicked"]`, and no errors at any step.

- **Typecheck.** `npm run typecheck` exit 0.

## Not verified

- `npm run bench -- replay`: this PR adds no goal, and the arena's benign-program test runs every goal against a
  mounted program with the default options (it passed). Paid agent runs (`npm run bench`) were not run.
- `render.sh` with the new options. It mounts with the defaults only, so the clock and input were driven through the
  arena and the scratch driver instead.
- Hosts that call `step` from inside a React lifecycle. If the program hasn't committed yet, `step` calls `flushSync`,
  which React refuses to do inside a render or commit and warns about in development.

## Gaps

- `render.sh` can't pass mount options or call `play`/`pause`/`step`/`setInput`, so a one-off driver was needed for
  the dist-built check. It could take `--clock host`, `--no-input` and a list of host actions.
