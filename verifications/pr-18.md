## Verified

- **loopway bot routing (not in the feature map): each issue starts exactly one of dev or epic, decided by `loopway:epic`.**
  The installed loopway 2.2.0 loads the bot files with its own `loadBots`, and `matchesLabels` routes sample label sets through them. The script is in the evidence folder as `route.mjs`. It imports `@loopway/cli/dist/bots.js` and, for each label set, prints the `on: issue` bots that match.
  `node artifacts/verify/20261127-105805-issue-16/route.mjs .`
  Saw:
  ```
  [] -> dev
  ["loopway:epic"] -> epic
  ["Loopway:Epic"] -> epic
  ["epic"] -> dev
  ["bug","loopway:epic"] -> epic
  dev "!loopway:epic" [ 'issue' ]
  epic "loopway:epic" [ 'issue' ]
  review undefined [ 'pull_request' ]
  ```
  Before the change, `node artifacts/verify/20261127-105805-issue-16/route.mjs <main checkout>` printed `-> dev, epic` for every label set, and `labels` was `undefined` for both bots.
- **The bot files still parse.** The same run loaded all three bots with no errors, and `review` is unchanged (`pull_request`, no labels).
- **The label exists on the repo.** `gh label list --repo mcwhittemore/thixo` shows `loopway:epic`.

- `npm run build` / `npm test`: no package source changed, only `.loopway/*.md`.
